## Rule
Unless a crate is explicitly platform- or hardware-specific, `cargo build` must succeed with nothing installed beyond `cargo` and `rustc`. Never shell out from `build.rs` to `make`, `cmake`, `protoc`, `perl`, `python`, or any other external tool, and never require an environment variable just to compile. If code must be generated from an IDL, run that generation at publish time and commit the resulting `.rs` file into the crate.

## Why
A `cargo install` can pull in hundreds of transitive dependencies; if any one of them needs an external compiler or interpreter to build, every user of every crate above it inherits a cryptic, environment-dependent failure. Once a working alternative exists, users switch away from crates that don't "just work" on a bare Rust toolchain.

## Do
```rust
fn main() {
    println!("cargo::rerun-if-changed=src/generated/schema.rs");
}
```
```text
src/
  generated/
    schema.rs   # generated by `protoc` once, at publish time, and committed
```

## Don't
```rust
use std::process::Command;

fn main() {
    // downstream users now need protoc on PATH to compile this crate at all
    Command::new("protoc")
        .args(["--rust_out=src/generated", "schema.proto"])
        .status()
        .expect("protoc must be installed");
}
```

## Notes
If a native toolchain step is unavoidable, isolate it behind an opt-in feature so the default build path stays dependency-free, and document the prerequisite loudly in the crate's README.
