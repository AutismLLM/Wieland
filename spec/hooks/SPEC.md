# Wieland — Enforcement Hooks Spec

Prompt rules *advise*. Hooks *enforce*. This is the L3 layer: fire on source writes (`.rs`, `.ts`/`.tsx`/`.mts`/`.cts`, `.go`) and on commit, run the corpus's `deny`-severity detectors, and block when they trip. Advice the model can ignore; a gate it cannot.

Status: **shipped** (`wieland hook` + `wieland install`, 2026-07-17). Validated live against Claude Code on a real project.

---

## Two enforcement points

1. **On write** (fast, advisory→blocking): right after an agent edits a Rust file, check *that file*. Cheap: `clippy` on the deny set, violations filtered to the edited file. Catches slop before it compounds.
2. **On commit / CI** (authoritative): the full deny set across the workspace. The line nothing crosses.

Both consume the *same* deny set — the rules with `severity: deny` (and their `detect.clippy` lints). One source, two gates.

## Claude Code (settings.json)

One-time setup: `wieland install` copies the corpus to `~/.wieland/rules` so the binary works from any project, then add:

```jsonc
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "wieland hook" }
        ]
      }
    ]
  }
}
```

`wieland hook` is the PostToolUse adapter. Field lessons baked into it (learned validating against a live harness — do not regress these):

- **Input is JSON on stdin**, per the Claude Code hook contract. `CLAUDE_FILE_PATHS` is NOT populated in every harness (empty in claude.ai/code sessions) — never rely on it.
- It extracts `tool_input.file_path` (or `tool_input.path`; joining `cwd` if relative), picks the language from the extension (`.rs` → Rust; `.ts/.tsx/.mts/.cts` → TypeScript, `.d.ts` skipped; `.go` → Go), no-ops on anything else, walks up to the enclosing manifest (`Cargo.toml` / `tsconfig.json` / `go.mod`), and runs the gate there scoped to the edited file (`gate --file`, span-matched — not `--changed`, which needs git and silently passes everything in a fresh repo).
- Corpus resolution: `WIELAND_RULES` if set, else `~/.wieland/rules`.
- **Exit 2 blocks** and feeds the rule-mapped violations back to the agent as tool feedback. Exit 0 is silent.
- **Only the edited file blocks.** Project-level findings (a missing required compiler option in a `tsconfig*.json`) are printed as advice on write and block in `gate --all` / pre-commit / CI.
- **Go runs** the pinned golangci-lint from `~/.wieland/tools/go/bin` over the module (`./...`) and keeps findings for the edited file.
- **TypeScript runs** the project's own `node_modules/.bin/tsc` if present, else the pinned one in `~/.wieland/tools/typescript`; oxlint always comes from the pinned tools.
- **Infrastructure failure never blocks an edit**: missing corpus, unreadable stdin, missing pinned tools, or a clippy/tsc/oxlint launch failure warn on stderr and exit 0. A broken hook must not brick the session.
- Hook configuration is snapshotted when a session starts — settings changes need a session restart to take effect.

`wieland inject-core` (UserPromptSubmit L0 injection) remains unbuilt — the compiled Claude skill already carries L0; build it only if a consumer without skills needs it (constraint 8).

## Other agents

`wieland hook --agent codex|cursor|gemini|pi` answers in each agent's own format; templates and the verification status live in `hooks/README.md`.

## Generic harnesses

- **git pre-commit** (`.git/hooks/pre-commit` or pre-commit framework): `wieland gate --staged`. Groups staged files per project root and language, so it works in monorepos; blocks the commit.
- **CI job**: `wieland validate && wieland gate --all`. Authoritative; required check on PRs.
- **Editor-agnostic**: `cargo clippy -- -D <deny-lints>` generated by `wieland compile deny-set` for teams that want plain clippy without the wrapper.

---

## Deny-set policy

- A rule is in the gate iff `severity: deny` **and** it has a reliable `detect` (clippy or ast — never grep alone, too noisy to block on).
- `warn`/`info` rules never block; they surface through MCP `review` and the prompt layers.
- Promotion `warn → deny` is a deliberate corpus edit, reviewed like any rule change, so gates never tighten silently.
- Escape hatch: standard `#[allow(...)]` with a `// SAFETY`/`// reason:` note. Wieland respects the compiler's own suppression — it does not invent a parallel ignore system.

---

## Failure ergonomics

A blocked write returns the rule, not just the lint: `id`, one-line `Why`, and `fix_hint`. The agent (or human) gets *why it's blocked and the idiomatic fix*, sourced from the same corpus that advised against it upstream. Enforcement teaches; it does not just say no.
